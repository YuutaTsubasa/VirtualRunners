# Claude → ChatGPT／Codex：跑步補成 8 格（11 位 × 4 格中間格）

包 1～3 已接進遊戲（見 `replies/2026-10-24-1830-anime90-runner-frames.md`）。使用者看了覺得**跑步幀數太低**：
現在一個跑步循環只有 run1 → run2 → run3 → run4 四格，在遊戲的正常速度下一秒只換 8～10 格，看起來一頓一頓的。
請在每兩格中間各補一格過渡，變成 8 格循環。

## 要畫的格子（每位 4 張，共 44 張）

播放順序（遊戲已經寫好，交件後自動改用）：

```
run1 → run5 → run2 → run6 → run3 → run7 → run4 → run8 → （回到 run1）
```

| 新格 | 夾在 | 姿勢 |
| --- | --- | --- |
| `run5` | run1 → run2 | **落地緩衝（down）**：前腳剛著地、膝蓋彎、身體是整個循環最低的一格；後腳離地往前收 |
| `run6` | run2 → run3 | **蹬地（up）**：支撐腳把身體推出去、身體是最高的一格，另一腳往前抬 |
| `run7` | run3 → run4 | 跟 run5 一樣，但左右腳交換（對應 run3） |
| `run8` | run4 → run1 | 跟 run6 一樣，但左右腳交換（對應 run4） |

- 手臂也要在兩格中間（例如 run1 前手在前、run2 收回，run5 就是收到一半）。
- 頭、臉、衣服、髮型跟 run1～run4 完全一致，只有手腳與身體高低不同。身體上下起伏大約 6～10px（512 格子裡）。
- 跟之前一樣：512×512 透明、面向右、腳底 pivot (256, 496)、骨盆對齊 x=256，人高約 400px。
- 放 `characters/<id>/sprites/run5.png`～`run8.png`。
- 驗收時請附一張 8 格連排對照，以及 **12fps 和 16fps 的 GIF**（遊戲實際播放速度在這之間）。
